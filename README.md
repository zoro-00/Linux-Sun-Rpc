# DCS Lab — Assignment 1, Part A
## File Handling Operations between Client and Server using Linux RPC (Sun/ONC RPC)

This project implements **Create, Write, Append, Read, and Delete** operations
on files, performed remotely by a client through a server, using classic
Sun RPC (`rpcgen`). Built and tested successfully on **macOS**.

## Project Files

| File                  | Purpose                                                       |
|-----------------------|---------------------------------------------------------------|
| `fileops.x`           | RPC protocol/interface definition (input to rpcgen)           |
| `fileops_server.cpp`  | Server-side procedure implementations (C++17)                 |
| `fileops_client.cpp`  | Menu-driven client (C++17)                                    |
| `fileops_svc.c`       | rpcgen-generated server dispatcher (patched for macOS)        |
| `fileops_clnt.c`      | rpcgen-generated client stubs (patched for macOS)             |
| `fileops_xdr.c`       | rpcgen-generated XDR serialization                            |
| `fileops.h`           | rpcgen-generated header (types + prototypes)                  |
| `Makefile`            | Runs `rpcgen` and builds `server` and `client`                |
| `run_macos.sh`        | Convenient helper script to check rpcbind and launch binaries |

> `fileops_svc.c`, `fileops_clnt.c`, `fileops_xdr.c`, `fileops.h` are
> auto-generated by `rpcgen fileops.x`. They have been patched with
> missing POSIX headers and `xdrproc_t` casts for macOS compatibility.

## 1. One-time setup (macOS)

```bash
# Install Xcode Command Line Tools (provides gcc, g++, rpcgen)
xcode-select --install

# rpcbind must be running on the server machine
sudo rpcbind -w
```

## 2. Build

```bash
make
```

This produces two executables: `server` and `client`.

## 3. Run the demo

**Terminal 1 — Start rpcbind (if not running):**
```bash
sudo rpcbind -w
```

**Terminal 2 — Start the server:**
```bash
./server
```
The server stores all files under `./server_files/` and logs every RPC call.

**Terminal 3 — Run the client:**
```bash
./client localhost
# or on a different machine:
./client <server-IP>
```

> **Tip**: You can also use `./run_macos.sh server` (Terminal 1) and `./run_macos.sh client` (Terminal 2) which automatically checks rpcbind and binaries.

You'll see a menu:
```
----- RPC File Operations Menu -----
1. Create File
2. Write File (overwrite)
3. Append to File
4. Read File
5. Delete File
6. List All Files
7. Upload File
8. Download File
9. Exit
```

### Suggested demo script

1. **Create File** → filename: `demo.txt`
   - Server prints `[SERVER] CREATE_FILE 'demo.txt' -> File created successfully`
2. **Write File** → filename: `demo.txt`, content: `Hello from RPC client!`
3. **Append to File** → filename: `demo.txt`, content: ` This line was appended.`
4. **Read File** → filename: `demo.txt`
   - Shows: `Hello from RPC client! This line was appended.`
5. **List All Files** → Option `6`
   - Displays all files currently stored on the server (`server_files/`) along with file sizes.
6. **Upload File** → Option `7`, local path: `./local_sample.txt`
   - Reads local file from client filesystem and uploads it to the server.
7. **Download File** → Option `8`, remote filename: `demo.txt`
   - Downloads file content from server and saves it to local destination path on client.
8. **Delete File** → filename: `demo.txt`
9. **List All Files** → Option `6` again to verify file removal.
10. **Exit**

This demonstrates all file operations happening on the **server's filesystem**
while being invoked entirely from the **client**, via RPC — nothing is done
locally on the client side.

## 4. Running on two different machines

- Both machines must be on the same network.
- Only `rpcbind` and the `server` binary are needed on the server machine.
- Only the `client` binary is needed on the client machine.
- Port `111` (rpcbind) must be reachable from the client.
- Run `./client <server-IP>` from the client machine.

## How it works (viva/demo explanation)

- `fileops.x` defines the RPC **interface**: the procedures, their
  argument/return types, and a unique program number (`0x31000099`).
- `rpcgen` compiles this into client stub code (`fileops_clnt.c`), server
  dispatch code (`fileops_svc.c`), and XDR marshalling code (`fileops_xdr.c`)
  that converts data between machine representations across the network.
- `fileops_server.cpp` contains the actual logic (`*_1_svc` functions wrapped
  in `extern "C"`) that runs on the server when a client calls the procedure.
- `fileops_client.cpp` calls the generated stub functions (e.g. `create_file_1()`)
  exactly like local function calls — RPC hides all network communication.
- `rpcbind` on the server acts as a registry: when the server starts it registers
  its program number and version; when the client calls `clnt_create()`, it queries
  `rpcbind` on port 111 to find the actual port, then connects directly.

## Architecture Overview

### Server
- **FileServer class** — encapsulates all file ops using C++17 `<filesystem>` and `<fstream>`
- `extern "C"` RPC handler functions bridge between C stubs and C++ class
- All files stored in `./server_files/` on the server machine

### Client
- **FileClient class** — manages the RPC `CLIENT*` handle and menu-driven UI
- Calls stub functions (`create_file_1`, `write_file_1`, etc.) like normal functions
- RPC library transparently handles serialization and network I/O
